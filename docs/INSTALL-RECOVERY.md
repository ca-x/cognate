# 客户端安装与恢复协议（开发中）

本文件描述 M2 的实现约束，不代表安装或恢复功能已经完成。`docs/REQUIREMENTS.md` 仍是产品需求的权威来源。

## 信任边界

- 客户端在可信本地文件系统上操作；来源目录、数据库、锁、canonical、staging、备份和 agent 目标的父目录及其路径链，在操作和恢复期间不能被不遵守协议的主体替换或修改。仅有 staging 目录的 `0700` 权限不足以保护其父目录中的目录项。
- CLI 和 GUI 必须使用同一个稳定的跨进程安装锁，先获取锁，再打开或迁移数据库、检查待处理操作、执行安装或恢复。advisory lock 只能约束遵守协议的进程，升级时不得与旧版本混写。
- 仅允许已验证的平台和文件系统实现执行实际安装。`os.Root` 限制路径访问范围，但不证明目录项身份；哈希、随机名称和数据库记录也不能单独证明文件属于 Cognate。
- 除非平台能确认目录项身份及其父目录在检查到操作期间稳定，否则不自动删除或覆盖；记录 `needs_attention`，保留现场供用户检查。

## 操作日志

- `planned`：操作意图及目标、slug 和路径保留已在一个数据库事务中提交。此状态下不得创建、替换或删除任何安装对象；因此可以事务性取消并释放保留。
- `active`：在任何文件系统变更之前，先以条件更新提交 `planned → active`。只有成功转换的执行者可继续；重复开始不能取得执行权。进程中断后必须由持有全局锁的恢复流程检查，不能仅凭状态重复执行。
- `needs_attention`：执行中出现无法自动判定所有权、冲突或其他不一致。保留相关资源的 claim 和磁盘现场；只有明确的协调流程才能继续或回滚。
- `cancelled`：仅未开始的操作可以进入此终态；状态变更和 claim 释放必须同事务提交。重复取消可安全返回。
- `completed`：仅可在全部必要目标与安装记录核对后进入；安装记录、终态和 claim 释放必须在同一数据库事务中提交。目前内部终态仅支持首次安装、一个 canonical 目标及零个或多个 symlink 目标；其他目标不能完成，尚未接入完整安装流程。

日志可按数据库顺序发现未完成操作，但不是操作系统对象所有权的证据。目标应逐项记录已提交的意图、预期内容、stage 名称及可验证的对象身份；创建对象后、身份写入数据库前崩溃的窗口必须进入保守协调，不能仅凭名字自动认领。

当前提供的保守协调只在新会话中执行：事务取消旧的 `planned`，将旧的 `active` 标为 `needs_attention`，并返回仍待处理的操作；不检查、认领或修改磁盘对象。逐项提交意味着中断后可以重复调用；一旦本会话创建新计划，就不能再调用此协调流程。该基础能力尚未接入安装命令，不是完整的自动恢复。

Linux 持锁会话可在当前会话启动的 active 操作中，按已记录的目标路径独占创建 stage，并在复制前把设备号和 inode 记录到目标日志。句柄由会话持有，调用方只获得路径；关闭会话会关闭句柄但不删除目录。创建、记录或复制失败时保留现场和 claims，并尝试标记 `needs_attention`；若数据库无法写入，标记可能失败，重开后仍需保守恢复。重复的数据库身份记录仅在值相同时幂等，不同值被拒绝。会话复制时核对身份及计划哈希，校验成功后条件提交每个目标的 `stage_ready`。该标记只代表此前完成过校验，不代表之后内容未改变，不能单独授权发布；重开后仍须保守协调。复制使用已打开的句柄，并在复制前后核对父目录和 stage 的当前路径身份；这些检查仍要求上述可信稳定路径前提，不能消除并发替换窗口。设备号和 inode 可能复用，只是辅助证据，不足以证明跨进程对象所有权，不能据此自动认领、发布或清理对象。其他平台的身份提取尚未实现，跨进程身份校验、完整安装及恢复尚未实现。

Linux 首次安装的 canonical 目标现在可在同一持锁会话内发布：发布前重新验证 stage 句柄、身份与内容（包括任何后来加入的 `.git`），先提交目标的 `publish_intent`，再以不覆盖 rename 发布；随后核对目标与原句柄的身份和内容，最后提交 `published`。两次数据库提交和 rename 不是一个事务；任一步失败时保留 claims 和现场，尝试标记 `needs_attention`，并且不自动回滚或认领对象。检查与按名称 rename 之间仍有竞态，只有上述可信稳定路径前提成立时该流程才可用；违反前提时即使返回错误也可能已经移动了错误对象，事后检查不能撤销该移动。

在同一持锁会话中，已发布的 canonical 可作为 symlink 目标：逐个提交发布意图后，在已存在的目标父目录中不覆盖创建绝对链接；持有 Linux `O_PATH|O_NOFOLLOW` 链接句柄，核验父目录、链接身份、链接文本及 canonical 后提交结果。已存在对象即使链接文本相同也不会自动认领；失败时保留现场和 claims。完成前重新核验所有本会话目标，然后将全部安装映射、终态和 claims 释放一并提交，并关闭本操作的句柄。链接创建与日志提交不是原子事务，重开后目前只保守标记 `needs_attention`，不自动认领或删除链接。此实现仅针对 Linux，检查 `/proc` 拒绝已识别的 WSL；WSL copy、其他平台实现和原生验证仍未完成。上述检查仍依赖可信稳定路径；例如在创建链接与首次打开句柄之间替换链接，可能错误认领替代对象，因此不消除非协议主体的替换竞态。

实验性 `install-local` 使用固定的 `~/.local/share/skillhub/` 状态目录和同一安装锁，从本地目录计算哈希、规划并执行上述安装；不存在的 agent skills 目录跳过，不创建。规划按现有目录身份去重，canonical 别名不生成自链接；不能假设能够识别所有挂载别名。状态目录必须由当前用户拥有且仅用户可访问，状态路径链拒绝符号链接、非 sticky 的其他用户可写目录及数据库末端链接；缺失目录相对已打开的父目录逐级创建，缺失的 canonical 目录若位于符号链接祖先下则拒绝创建。CLI 持锁检查来源、canonical 和现有 agent 目录及逐跳符号链接路径的属主和权限；这些检查仍要求路径稳定，且只在 CLI 接入层执行，低层调用者须自行遵守同样的信任边界。`install-status` 可列出待处理操作及目标，`--reconcile` 持锁取消未开始操作、将已开始操作标记为需关注，不删除现场。该入口不提供对需关注操作的人工处理界面，也不实现自动恢复、更新或卸载。数据库层的完成方法只检查日志，必须由持锁并核对文件系统的会话调用，不能单独作为所有权证明。安装终态事务现在会保存发布时的设备号和 inode 辅助证据；旧记录保持空值，不因只读去重自动补录。即使有这些证据，inode 可复用且路径可能被替换，仍不能据此授权卸载或清理。M2 未完成。

重复本地安装仅在现有记录的 slug、内容哈希和全部规划目标一致，且 canonical 内容（包括后来加入的 `.git`）及所有链接目标均经只读核验后返回成功，不修改或重新认领对象。安装内核对来源树及现有 canonical 树检查属主与写权限；对于有身份记录的新安装，还将当前对象身份与记录比较，源内容会再次校验。目标缺失、内容变化、身份不符或 agent 集合变化时保守报冲突。此规则不提供持久对象所有权证明，也未实现 pack 引用计数、增量添加投影或更新，不能视为 F5 的完整去重。

新计划会检查已有安装的 slug 及路径（包括祖先/后代关系）；独立创建安装记录也会检查待处理操作的 slug、目标和 stage 保留。一般冲突检查拒绝与已有记录重叠，绑定备份的卸载计划有下述受限例外；update 和实际卸载仍须建立明确的所有权规则，不能简单放开。检查仍依赖各写入者使用统一协议及可信稳定路径，不能防御绕过协议直接写数据库或替换路径。

卸载日志基础现可记录绑定备份的专用计划：它要求非空安装代次，精确匹配全部 canonical/symlink 映射、每个记录的身份、备份来源和快照身份，并预留备份及目标与同目录隔离名；其他安装、备份和待处理操作仍参与冲突检查。重开及开始时再次核对数据库记录，不一致则拒绝继续。每个目标的移动意图和结果分开记录，要求先处理所有投影，最后处理 canonical；所有目标移动后，逐目标记录隔离项清理意图及结果，全部清理完成才在同一事务删除安装映射、更新操作状态和释放 claims，备份记录保留。该数据库协议不会读取或修改文件系统，不证明对象仍存在、快照仍完整或对象归属，也不授权 rename、删除或卸载；调用方必须持锁并验证实际对象后才能调用进度和完成方法。`planned` 可以取消，实际卸载和自动恢复仍未实现。旧记录没有安装代次或身份时不能使用此专用计划；旧版未绑定备份的待处理卸载日志会被拒绝，须人工检查，不得自动认领。

实验性 `Session.PrepareUninstallLocal` 仅在 Linux 非 WSL 持同一锁检查现有安装、canonical 内容和投影链接，建立新的本地备份并重新校验备份快照，随后建立上述 `planned` 记录；不移动、删除或认领任何已安装对象。成功返回备份及操作 ID，调用者可取消未开始的计划；备份完成后计划失败时备份仍保留。该入口尚无 CLI，且只提供前置准备，不证明跨进程连续所有权，不能将其计划直接用于自动删除。低层调用者须保证可信稳定路径及统一锁协议；旧安装即使有 inode 身份也不因此获得自动卸载权限。

数据库 schema 迁移与随后对旧日志及 claims 的校验不是一个整体事务；即使旧日志异常导致打开失败，schema 升级也可能已经提交。失败时保留原有日志供检查，不得假定数据库完全未发生变化。

来源路径可能在解析与打开之间被替换。CLI 校验原始来源路径的逐跳语义，并将解析后的路径传给安装内核；哈希前检查将被复制的来源树对象须由当前用户或 root 拥有、不得被其他用户写入，跳过不会复制的 `.git` 目录。内核在元数据检查、哈希和复制前统一解析来源，避免 `symlink/..` 被不同阶段解释为不同目录。计划中的安装必须使用可信来源预先确定并记录的内容哈希，在打开来源句柄后先核验内容，再复制并对持有的 stage 句柄计算哈希；不匹配时保留现场并停止。`CopyFromVerified` 提供这项内容检查，但哈希不证明文件对象所有权，也不能代替稳定的来源、stage 路径和内容；普通 `CopyFrom` 不提供该保证。权限检查不排除其他主体早已取得可写句柄或违反路径稳定前提，低层调用方仍须确保来源可信。

会话复制将请求 context 传递给遍历、哈希和文件读取，取消后停止后续读取并保留已有现场；已取消的请求在进入复制前不会等待互斥锁，但进入锁等待后再取消不能直接唤醒等待者，已经阻塞的文件系统系统调用也不能保证立即中断。取消可能使状态写入失败，此时必须重开会话协调，不得假定已经标记 `needs_attention`。

## 后续执行步骤

1. 锁内检查未完成日志；未验证恢复规则前，不开始新的文件系统操作。
2. 提交安装意图并转为 `active`；在目标所在文件系统的可信私有父目录中独占创建 stage，记录可验证的身份，复制并校验快照。
3. 先持久化每个发布意图，再使用该平台经过验证的不覆盖原子发布；发布前后确认对象身份。对 agent 投影分别记录进度，不能把多个目录视为一个原子事务。
4. 卸载前创建备份；仅在可信父目录内、对象身份与记录相符且内容冲突策略允许时移除 Cognate 自己的对象。
5. 每个日志和文件系统步骤都要进行进程中断测试，并重复恢复验证幂等性；身份不明、对象被替换、内容被用户修改或日志与磁盘矛盾时停止自动处理。

SQLite 事务和文件系统 rename 不能组成单一原子事务。目前只计划验证进程崩溃恢复；未验证文件与目录同步顺序之前，不承诺断电持久性。Windows junction、copy 回退、WSL copy、大小写规则和 macOS/Windows 原生语义均需平台实测。

`CopyAllFromVerifiedContext` 可校验并复制包含 `.git` 的目录内容，但按路径重新打开来源，不能绑定此前检查过的对象。`CopyAllFromRootVerifiedContext` 从调用方持有的来源句柄读取，并在复制前后核验内容及子项权限；调用方仍须验证该句柄与计划目标及父目录的关系。两者复制子目录和文件的普通权限位，但不保存根目录权限、属主、时间戳、ACL、xattr 等全部元数据，也没有备份事务日志或发布流程，不能单独作为完整备份或卸载依据。

实验性 `backup-local` 为已安装 skill 创建 `skillhub-snapshot-v1` 本地快照：持有安装锁和来源目录句柄，计划中记录安装代次、来源路径及辅助身份、包含 `.git` 的当前内容哈希、子项权限摘要和根目录权限；stage 和最终路径在私有备份目录中保留。发布意图先于不覆盖 rename 提交，发布结果、备份记录、完成状态和 claims 释放在同一 SQLite 事务中提交。备份会保留普通文件及子目录的权限位，并在记录中保存来源根目录权限；属主、时间戳、ACL、xattr、特殊文件及符号链接不属于此格式的保存范围，遇到不支持的对象时拒绝备份。备份内容未加密，可能包含 `.git` 或其他敏感文件；状态目录须保持私有。备份后卸载尚未实现，备份记录不能证明来源所有权或授权删除。中断及结果不确定时保留现场和 claims，使用 `install-status` 检查；不承诺断电持久性。

`backup-list` 在同一安装锁下列出数据库中已完成的备份 ID、skill 名称、格式和路径；它不读取或验证快照内容，也不能证明备份仍存在或可恢复。查询现有数据库时可能执行数据库迁移；没有状态数据库时不会创建它。

实验性 Linux `restore-local BACKUP_ID PARENT NAME` 向可信的现有父目录发布此前不存在的新目录，不覆盖现有对象，也不创建安装映射或赋予卸载权限。持锁恢复验证打开的备份身份、内容和子项权限，计划记录 backup ID、快照元数据及来源、stage 和目标 claims；发布意图先于不覆盖 rename，之后对持有的目录句柄恢复根权限并检查身份，发布结果、完成状态和 claims 释放在同一事务中提交。未能确认结果时保留现场和 claims，保守协调不自动清理或重试。根权限可能允许其他用户读取，也可能使目录不可读取；`0000` 等权限设置后不能再依赖遍历内容进行校验。进程退出的全部窗口、磁盘满及非协议替换尚未完整验证，恢复功能仍在开发中。

恢复操作的 pending claims 在重开时会重新核对备份记录、路径和快照元数据；记录缺失或矛盾时拒绝打开状态库，保留原始日志和 claims，不会自动认领或删除文件。CLI 检查目标父目录的路径链与权限；低层会话调用者必须自行执行同等检查。非协议路径替换仍可能发生 TOCTOU，持有句柄和身份核对不能消除该风险。

后续卸载不能仅凭 marker、硬链接锚点、设备号/inode、内容哈希或备份记录认领目录及子项：marker 可被移植，目录无法硬链接，inode 可复用，内容相同也不能证明目录项连续归属。缺少可验证的连续所有权时必须停止并保留现场，尤其不能对仅凭 marker 匹配的目录递归删除。备份完成只满足卸载前备份的要求，不授权删除。
