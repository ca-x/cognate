# Server Local Snapshot (B2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This document grants no source writes, commits, delegation or product enablement; obtain main's exact source grant first.

**Goal:** Give a managed Store a bounded, read-only SQLite candidate and all-instance reference inventory inside one retained Exclusive, without claiming a usable backup.

**Architecture:** Independently pin Store lifetime before Quiesce, bind the actual database identity, copy via the pinned modernc paged Backup API, then validate only the closed candidate. A synchronous trusted consumer receives an opaque scoped view; reader close, cleanup, Exclusive release and unpin must succeed before any nonzero summary escapes. Uncertain resources transfer to cached poison ownership rather than dropping the physical instance lock.

**Tech Stack:** Go1.27.3, CGO_ENABLED=0, existing ent/SQLite/modernc1.60.1/entsqlite0.2.6, JSON v2, physical OS roots. No new dependency, schema or generated code.

**Spec:** `docs/superpowers/specs/2026-10-29-server-local-snapshot.md`, SHA256 `8b9f6f19611d7d6cabc8af253a1ceb8eca7a5255d8a8de0d88a4d7bfd2f309f8`; total contract `2026-10-28-server-backup.md` §3.1/§11 and REQUIREMENTS F4.

## 3. Fixed API and private contracts

```go
type LocalSnapshotLimits struct {
    MaxDBBytes, MaxInventoryBytes, MaxRecords, MaxStagingBytes int64
    DrainTimeout, OperationTimeout time.Duration
}
func (store *Store) WithLocalSnapshot(context.Context, LocalSnapshotLimits,
    func(context.Context, LocalSnapshotView) error) (LocalSnapshotSummary, error)
func (view LocalSnapshotView) Metadata(context.Context) (LocalSnapshotMetadata, error)
func (view LocalSnapshotView) References(context.Context, LocalSnapshotCursor, int) (LocalSnapshotPage, error)
func (view LocalSnapshotView) CopyDatabase(context.Context, io.Writer) (int64, error)
func (summary LocalSnapshotSummary) Metadata() (LocalSnapshotMetadata, bool)
```

- `LocalSnapshotView`, `LocalSnapshotSummary`, `LocalSnapshotCursor` are closure-backed opaque values, not structs containing sensitive pointers/strings/slices reachable through private formatting carriers. Fixed Format/String/GoString/LogValue/MarshalJSON render only redaction. Zero view/cursor misuse refuses; zero summary Metadata returns zero, false. An actual successful summary holds an immutable metadata clone; errors always return the zero wrapper. No public constructor, source path, DSN, handle, Instance or Exclusive argument.
- Metadata is an explicitly requested value copy with fields `Format string`, `Version int`, `ContentClosure string`, `ID string`, `DBBytes int64`, `DBSHA256 string`, `SQLiteVersion string`, `SchemaSHA256 string`, `ReferenceBytes int64`, `ReferenceSHA256 string`, `Counts LocalSnapshotCounts`; counts contains `Repositories, Skills, Packs, PackItems, Total int64`. Metadata/reference DTOs are privileged data obtained explicitly, not safe log payloads or owner-facing RPC types. No created-at/global revision field.
- Cursor zero starts at the beginning. Nonzero cursor is unforgeable per-view/run identity plus private byte offset/record ordinal; foreign/expired cursors fail. Page has `Entries []LocalSnapshotReference`, `Next LocalSnapshotCursor`, `Done bool`; requested size must be1..128. Entries contain `Kind string`, `ID int64` plus exactly one typed repository/skill/pack/pack-item payload matching §4. No user SQL, arbitrary offset/filter/owner selector. Pagination reads the sealed NDJSON, never live ent.
- Repeated CopyDatabase starts at byte0, streams through a fixed64KiB buffer, enforces exact bytes/hash/EOF and scoped context; caller owns writer. Do not close or concurrently mutate caller resources, buffer the DB, return a file or create an async copier. Trusted caller must supply bounded synchronous local I/O; arbitrary blocked callback/writer cannot be forcibly interrupted.
- Every view method checks both its retained operation context/live generation and the supplied child context; background/new deadlines cannot extend the owning scope. Admission increments a view-local in-flight count; callback return revokes new admissions and drains admitted methods before unlink. Metadata/page methods return zero values on any error; CopyDatabase returns0 on error as a result-withholding rule, not a claim that the caller's writer received no partial bytes. No rollback of caller output is promised.
- Private state includes `snapshotIdentity` (canonical parent, basename, retained parent/file identities), separate pin count and a snapshot-context marker. `pinSnapshot(ctx)` returns scoped ctx/release or a fixed error; never calls Enter(writer). A private per-operation runtime owns actual source/target/read/file operations and stage barriers, permitting test wrappers around real operations without global hooks/public injection.
- Private poison lifetime root, in the already proposed `maintenance.go`: package-scope `localSnapshotPoisons` owns a mutex and `map[*snapshotPoisonPayload]struct{}`. One sealed payload per uncertain operation is inserted exactly once and never removed or retried before process exit; duplicate transfer of that same payload is idempotent. The actual strong edge is package global → map key → payload → all pending source pool/Conn, Backup/destination handles, staging files/roots, original Store client/lifecycle ownership and exact Instance/Exclusive/DB identity. Retain every still-available uncertain object, not only its path/FD/error description; record lost-driver-handle uncertainty without pretending to recover that handle. This holder is separate from view/cursor admission and the maintenance directory registry; neither a self-cycle, the existing directory registry nor runtime.KeepAlive supplies this missing edge. It has no public lookup/recovery API, finalizer, worker or deletion path; known-closed cleanup orphans never enter it. The payload is private and never formatted/logged.
- Fixed exported errors: `ErrLocalSnapshotUnmanaged`, `ErrLocalSnapshotIdentity`, `ErrLocalSnapshotBusy`, `ErrLocalSnapshotBudget`, `ErrLocalSnapshotInvalid`, `ErrLocalSnapshotCleanup`, `ErrLocalSnapshotUncertain`. Preserve errors.Is for ctx cancellation/deadline and existing maintenance closed/unsupported/lease/quiescing classes. Never wrap raw driver/SQL/path/row/callback errors. Internal classification may inspect numeric SQLite codes; text matching is forbidden.

## 4. Frozen local format and independent checker oracle

Namespace is `.cognate-local-snapshots` under the Store canonical dataDir,0700; each operation creates a fresh crypto/rand16-byte lowercase32hex subdirectory,0700. Fixed files are `snapshot.sqlite`, `references.ndjson`, `candidate.json`, each regular0600/single-link. Reserve files O_EXCL. Existing unknown namespace contents are not traversed/removed. Use physical `os.Root` and inode/owner/mode/link validation; Afero's cache/object-store interfaces cannot virtualize SQLite files or prove physical identity. No injected Afero FS/paths. Future remote storage remains a separate Afero capability task.

`candidate.json` has exactly the following lower-camel-case keys in this canonical order: `format`, `version`, `contentClosure`, `id`, `dbBytes`, `dbSha256`, `sqliteVersion`, `schemaSha256`, `referenceBytes`, `referenceSha256`, `counts`. Counts order: `repository`, `skill`, `pack`, `pack_item`, `total`. Values are format=`cognate-local-sqlite-candidate`, version=1, contentClosure=`not-included`; SHA fields are lowercase64hex. No key ID/proof, secret, owner name, raw credential, filesystem path or readiness flag in metadata.

Each NDJSON line is one UTF-8 JSON-v2 object plus LF, with exactly these keys/types in order; all numeric IDs/counts/revisions are positive signed64-bit values, except zero actual child counts only if already legal in the existing domain:

| kind/order | Fields after `kind`, all required |
| --- | --- |
| `repository` | `id`, `publicId`, `ownerId`, `canonicalRepo`, `branch`, `archiveHash`, `skillCount`, `revision` |
| `skill` | `id`, `publicId`, `repositoryId`, `path`, `contentHash` |
| `pack` | `id`, `publicId`, `ownerId`, `revision`, `itemCount` |
| `pack_item` | `id`, `packId`, `skillId`, `slug` |

Payload types are `LocalSnapshotRepositoryReference`, `LocalSnapshotSkillReference`, `LocalSnapshotPackReference`, `LocalSnapshotPackItemReference` with corresponding PascalCase Go fields. OwnerID is existing user primary key, repository revision is publication_revision, Pack revision is revision. CanonicalRepo/branch/hash/path/slug/public IDs use current domain normalization/validators, not newly accepted syntax. References retain all owners/private/unpublished/unpacked rows; do not deduplicate shared archive hashes here.

Use encoding/json/v2 with duplicate-name rejection and unknown-member refusal; reject invalid UTF-8, extra roots/trailing bytes, extra/absent fields, mismatched union/kind/version, unsorted/duplicate IDs and counts/length/hash mismatch. Metadata≤64KiB including LF; each complete reference line≤64KiB including LF. Read bounded bytes before decoding. A short line at EOF without LF is invalid. Output limits checked before write; decoder/re-encoder must not silently normalize damaged input into success.

Schema validation is an allowlist, not self-approval of target-derived fingerprints. Task0 freezes an in-test literal manifest from the **fixed baseline's** generated `ent/migrate/schema.go` and independently created known-good baseline fixture, before candidate code is implemented. Manifest enumerates every application table, column ordinal/name/declared type/nullability/default/PK, explicit index uniqueness/ordered columns/predicate and FK target/columns/actions. Include the actual baseline compatibility schema, especially catalog_integrity.go's four `skillhub_membership_owner_insert`, `skillhub_membership_owner_update`, `skillhub_list_owner_immutable`, `skillhub_repository_owner_immutable` trigger definitions; do not reject a legitimate baseline by looking only at ent table declarations. Do not omit session/config/native/source tables, infer the allowlist from the candidate, or regenerate the expected literal on test execution. Normalize using SQLite table_xinfo/index_list/index_xinfo/foreign_key_list: sorted binary names, columns by cid, index/FK tuples by their canonical bytes; preserve normalized SQL for CHECK/predicate/expression/trigger definitions, collapsing whitespace only outside quoted literals. Reject extra user tables/indexes/views/triggers and virtual/generated definitions not in the allowlist. SQLite internal bookkeeping objects are classified explicitly in the fixture, not accepted via a broad unknown-table prefix rule.

Canonical fingerprint encoding is domain `cognate/sqlite-schema/v1`, followed by ordered manifest records; each UTF-8 field is prefixed by its8-byte big-endian length, integer/bool attributes encoded as canonical decimal strings. Schema SHA is SHA256 of that stream. Freeze the actual expected hash literal in Task0 alongside the literal manifest after independently matching generated schema and baseline fixture; production embeds that reviewed manifest/hash in local_snapshot.go. This is a deterministic implementation step, not an invitation to accept a newly computed candidate schema or add a migration version. New application schema later requires explicit manifest/review update.

The checker uses private parameterized database/sql queries, opens only the completed target with mode=ro+immutable, and gives the reader pool one close owner; it never calls state.Open/Schema.Create/verifyDatabaseKey/normalization/history backfill or closes a shared pool through both ent and SQL. Verify integrity_check yields exactly one `ok` and FK check yields zero rows; close/error-check every Rows. Read credential-key-v1 identity/proof using existing Store keyID/aead, match the exact existing AAD/plaintext; observation-policy proof likewise uses existing store observationMaxAge. Missing/incorrect proofs fail, no enrollment/repair. Clear decrypted proof bytes. Unknown metadata names are not key authority. Hash DB before/after checking, reject any new sidecar or altered bytes.

Read references with primary-key keyset queries (`id > last ORDER BY id LIMIT128`), fixed kind order. Query octet lengths before fetching large text/blob fields into Go; precheck encoded-size worst case (JSON escaping included), then encode/recheck. Verify child counts with indexed bounded/streaming queries, public-ID/relationship uniqueness, owner consistency and no dangling Pack→skill→repository; enforce existing domain rules without mutating invalid rows. No All without LIMIT, ReadAll, OFFSET scans, giant IN lists or all-ID maps. Non-reference tables remain byte-for-byte in the physical DB; no secret expansion into inventory.

## 5. Resources, budgets and stage machine

All6 limits must be positive and arithmetic fit int64. Set operation ctx to min(caller deadline, now+OperationTimeout) before pin/queue; drain ctx adds min(remaining, DrainTimeout) solely around Quiesce. No success on late cancellation. A deadline does not permit abandoning uninterruptible fsync/Close/Step; always join synchronous cleanup before returning.

Before creating the operation directory/target, admit checked `DBBound=page_size*page_count≤MaxDBBytes` and `DBBound+MaxInventoryBytes+65536≤MaxStagingBytes`; reserve the full sums, not expected row size. Page_size must be a supported SQLite power-of-two512..65536. Count all freelist/deleted/sparse pages. Source page_count=0/overflow/inconsistent header fails. Host writers cap reference bytes/record count and metadata; target SQLite file may never exceed DBBound and no other SQLite target files are allowed. Directory allocation and volume blocks are not logical-byte budget guarantees; preflight free space is informative, ENOSPC still fails. B3's second DB/inventory/archive/encryption workspace has a separate aggregate charge.

At most one source Conn/pool, one raw destination, then one checker at a time; close stages before advancing. Step size64 is not total RAM. Hold only128 bounded rows,≤64KiB line buffer,≤64KiB metadata and64KiB copy buffer. Tasks0/1 audit pinned pager/backup/integrity code and report a DBBound/page_count-derived conservative working-set estimate including both pager caches and integrity bookkeeping; configure cache_size=-256 and temp_store=MEMORY as optimizations, not hard RAM limits. Use `2*DBBound + 128*page_count + 128*(2*65536+2048) + 16*65536 + schemaManifestBytes` as the conservative planning envelope to validate against that source audit and actual512/65536-page/freelist fixtures. It is not a process RSS/physical-memory quota; if an engine structure/workfile cannot be bounded by the audited model, stop the capability gate and request revision, not a fabricated memory guarantee. Record peak runtime/process memory and actual files at barriers; no unrestricted SQL sorter/temp-file materialization.

| Stage | Ownership and required transition |
| --- | --- |
| Admission | ctx/basic limits/platform/nil/unmanaged/closing/poison check; stable DB identity; pin, mark scoped ctx, then own-instance Quiesce; no writer lease |
| Drain | Reject recursive/writer/stale context. Retain pin while queued. Exclusive validated for own Instance. Recheck exact parent/DB and budgets before staging |
| Backup | Open source URI mode=ro, **not immutable**, max-open/idle1; no journal/checkpoint/schema changes. Conn.Raw narrow NewBackup interface, reserved target mode=rw with OFF pager only for disposable candidate; explicit matching target page_size |
| Step | Same Raw callback, Step(64), check ctx/identity/page progress/DBBound/files before and after each call. SQLITE_BUSY/LOCKED: at most20 retries with cancellable10ms waits, still inside operation deadline; no restarted backup or gate release. Source busy_timeout=0 so Step cannot inherit10s source-store waits |
| Terminate | Every created Backup: exactly one Commit, never Finish. Step false means completed, true means continue. Destination returned by Commit gets one explicit checked driver.Conn.Close. Conn.Close and pool.Close each checked; no Raw handle escapes except strongly retained poison ownership |
| Durability | Once all write handles are certainly closed: validate inode/type/mode/link, File.Sync+Close, sync staging and new staging-parent entries. Do not patch SQLite header or apply OFF to live DB; acceptance rests on independent readonly content/no-sidecar gate, not fabricated header bytes |
| Check/seal | Open target reader; schema/key/integrity/relations, bounded references and metadata. Hash-before/after checks; close every reader/rows, sync all3 files and directory. Re-read strict sealed local format before consumer |
| Consumer | scoped live view only; all CopyDatabase/References read same sealed files, check count/hash/length and ctx. No network/KDF/JS/new domain writes. Return revokes new view calls and drains already admitted calls before deleting files |
| Finish | Close remaining readers, remove only owned3 files/subdir, sync parent, final identity/ctx checks, then Release Exclusive and unpin. Only now construct nonzero summary. Callback result alone never publishes success |

NewBackup creation failure is conservatively uncertain once target creation may have entered the driver, since newConn/backup error branches can discard Close results. Commit error likewise can internally discard destination Close. Explicit Close error or lost handle ownership also poisons; do not call Commit/Close repeatedly to guess recovery. Definite pre-NewBackup input/open refusal with all acquired handles checked-closed can clean normally. A successful finish of an incomplete/canceled backup remains failure.

Snapshot pin is separate from `storeMaintenance.active` writer count. Close sets closing, blocks new roots, allows already-live nested writer drain under existing semantics, waits both counters, closes original ent client, then releases instance. Do not hold lifecycle mutex while waiting for Quiesce/SQL/callback/close. On snapshot uncertainty, seal and insert the payload into `localSnapshotPoisons` before terminating the operation pin or dropping any local ownership; under the lifecycle mutex publish closing/poison/cached ErrLocalSnapshotUncertain, revoke the view and drain already-admitted view methods before pin termination. Holder insertion is the sole lifecycle-mutex → holder-mutex order; no holder operation acquires a lifecycle mutex, calls Close or performs I/O. No driver-private lost handle is recovered by reflection/reopening. A concurrently waiting Close rechecks poison after every drain wake and immediately before the normal SQL-close/instance-release tail; poison returns the same cached error promptly without waiting on its own retained Exclusive, releasing any retained root or retrying handles. Other managed Stores on that gate still cannot enter writers. Dropping caller Store/view/payload references cannot release poison ownership: the package-level holder survives until process exit, not garbage collection or a hidden finalizer. Preserve normal B1 writer drain and SQL-close-error lock retention unchanged.

If handles definitely closed but deletion/sync fails, return cleanup error and zero summary, retain only an explicit private orphan description, release gate/pin; no false SQL poison or ready receipt. No auto-orphan scanner/reuse here. Panic invalidates view and follows the same cleanup/poison transfer before re-panicking, never returns success. Callback raw errors map to fixed invalid unless cancellation/controlled error classification applies; no sentinel leak via errors.Join.
