# GitHub 仓库拉取代理

管理员登录 Web 后，在“服务端日志”页面的“GitHub 网络代理”区域设置正向代理。
支持 `http://`、`https://`、`socks5://` 和 `socks5h://`，例如：

```text
http://192.168.1.20:7890
socks5h://192.168.1.20:1080
```

填写完整代理地址并保存，无需重启。需要代理认证时可填写 URL 编码的用户名/密码；
现有密码不会回显。成功后输入框清空，页面只显示不带认证信息的代理 endpoint。
清除设置恢复 Go 的环境代理规则（`HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`），
并非强制直连。环境变量仍由服务进程启动环境提供，修改环境变量须重新启动进程。

## 懒猫与 Docker

代理必须能从运行 Cognate 的容器内访问。`127.0.0.1` 指容器自身，不是电脑或宿主机；
代理在其它设备上时，应填写其局域网地址，并在代理软件中允许该容器/盒子访问。
不要为方便连接而把代理端口无鉴权暴露到互联网。

## 范围与安全

- 只影响服务端 GitHub 仓库内容获取、私有仓库权限元数据检查和来源刷新；CLI/GUI
  通过服务端安装技能时自动受益。不改变 OIDC、S3 备份或其它外部服务的网络路由。
- 仍然访问原始 GitHub HTTPS 域名并验证 TLS。它不是 `ghproxy` 一类 URL 下载镜像，
  不支持给镜像站转发 GitHub token。HTTP CONNECT 仅把代理认证交给代理，GitHub
  凭据在到 GitHub 的 TLS 连接内传输；归档跳转沿用原有严格的目标与凭据策略。
- 保存后新请求使用新代理；已有请求不被强行切断，也不会因代理修改而自动重放。
- 参数是实例级管理员设置，普通账号和匿名用户不能读取或修改。凭据使用服务端
  master key 派生的独立密钥加密保存在数据目录的 `network/github-proxy.enc`；不要
  更换 master key。普通备份恢复不会覆盖本机网络参数，迁机时须重新设置。
- 保存结果不确定时，先重新读取生效状态；不能把取消等待当作撤销或自动重试保存。
  校验失败或连接失败的日志和错误消息均不包含代理地址中的秘密值。
  若服务端检测到持久化状态不确定，会停止接受 GitHub 请求及代理更新；此时重新读取
  也会失败，须排除存储故障后重启服务端。正常保存、清除代理均无需重启。
- 独立的 CLI `browse` 使用 Git，遵循 Git 自身的环境代理配置；不读取服务端后台设置。

仓库来源可先离线登记，再配置代理并点击“同步技能”；下载失败不会删除来源记录。
详见 `IMPORT-SELECTION.md` 和 `REPOSITORY-LIBRARY.md`。
